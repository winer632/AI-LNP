GO-017：一个未解决的召回缺口GO-017: An Unsolved Recall Gap

交接给 Codex · 2026-07-29 · 仓库 ~/Desktop/LNP/AI-LNP · 当前 recall 13/15 Handoff to Codex · 2026-07-29 · Repository ~/Desktop/LNP/AI-LNP · Current recall 13/15

请你判断的问题：有没有一种正当的办法让 GO-017 被匹配上。 The question for you: is there a legitimate way to make GO-017 match?

「正当」的定义在第 5 节，它比问题本身重要。 已经有 9 种方案被试过，8 种失败，其中 4 种是因为跨越了那条线而被主动否决 —— 它们能提高数字，但那个数字不再代表任何东西。「无解」是一个可接受且有用的答案。 What counts as legitimate is defined in section 5, and it matters more than the question itself. Nine approaches have been tried and eight failed. Four of those were refused deliberately: they would have raised the number, but the number would no longer have meant anything. "There is no legitimate way" is an acceptable and useful answer.

1. 这个项目在做什么1. What this project does

从 9 篇 LNP（脂质纳米颗粒）论文中抽取实验结果，与人工标注的 15 条金标准（gold set）比对。 评测器做一对一确定性匹配：每条 gold 只能配一条抽取记录，同一输入必得同一结果，可逐字节复现。 It extracts experimental outcomes from 9 lipid-nanoparticle papers and compares them against a hand-annotated gold set of 15 outcomes. The evaluator performs deterministic one-to-one matching: each gold row can claim at most one extracted record, the same input always yields the same result, and the result is byte-reproducible.

指标Metric 当前Current 含义Meaning
recall13/15 15 条 gold 中找回 13 条，缺 GO-017、GO-018 13 of 15 gold outcomes recovered; GO-017 and GO-018 missing
precision0.2203 输出 59 条记录，13 条对上 gold 59 records emitted, 13 matched a gold row
evidence accuracy7/12 匹配记录里，引用证据确实支持其说法的比例 Of matched records, how many are actually supported by the evidence they cite

precision 低不代表 73% 是错的。那 46 条未匹配记录里混着三类：真正多余的、 论文里真实存在但 gold 没标注的、以及同一结果被拆成多条的。评测器一对一匹配， 多输出记录只会降 precision —— 所以任何「多捞一条」的方案都自带 precision 代价。 Low precision does not mean 73% of the output is wrong. The 46 unmatched records mix three kinds: genuinely spurious ones, results the paper really reports but the gold set never annotated, and one result split across several records. Because matching is one-to-one, emitting more records can only lower precision — so every "recover one more" idea carries a precision cost by construction.

endpoint_name 分词后是 ['activated', 'elimination', 'hsc']， 三个词在 15 条 gold 里都属于罕见词（全局出现 ≤2 次）。这一点在第 4 节的门判定里很关键。 endpoint_name tokenises to ['activated', 'elimination', 'hsc'], and all three are rare across the gold set (each occurs at most twice globally). That matters for the gate logic in section 4.

So the gold row's activated HSC and the record's FAP+ JS-1 denote the same population. The gold set names the cell type; the paper names the cell line.

论文从没在一句话里说过 JS-1 是什么。信息在，但要两跳： The paper never states what JS-1 is in a single sentence. The information is there, but it takes two hops:

4. 为什么匹配不上 —— 门的判定4. Why it does not match — the gates

评测器有三道门，任何一道不过则得分归零。相关的两道 （src/extraction/evaluate_final_gold_dynamic.py）： The evaluator has three gates; failing any one zeroes the score. The two that matter here (src/extraction/evaluate_final_gold_dynamic.py): 

endpoint_gate = bool(
    endpoint_overlap
    and (
        exact_numeric
        or text_numeric
        or (
            (rare_endpoint_overlap and len(endpoint_overlap) >= 2)
            or len(qualitative_overlap) >= 3
        )
    )
)

polarity_gate = (
    not distinctive_qualitative
    or bool(distinctive_qualitative & outcome_only_tokens)
)

distinctive_qualitative 是 gold 的 qualitative 文本与一个固定词表的交集， 词表为 {few, no, obvious, solely, eliminated, eradicated, localized, colocalized, reduced, defenestration}。GO-017 的判别词是 eliminated。 distinctive_qualitative is the intersection of the gold row's qualitative text with a fixed lexicon: {few, no, obvious, solely, eliminated, eradicated, localized, colocalized, reduced, defenestration}. GO-017's distinctive term is eliminated.

什么是可以的What is allowed

  • 让抽取产出更完整、更真实的信息 —— 例如让实体信息一致地到达每一条引用了同一细胞系的记录。 这是修一个不一致，不是放松尺子。
  • 修一个正在错误丢弃正确结果的缺陷。已验证有效 唯一成功的那次就是这类：一条虚构的 evidence id 出现在 eligibility 字段里， 导致整个响应连同六条正确记录一起被丢弃，其中一条正是另一个缺失结果 GO-002。
  • 一切改动必须挂在开关后面（config/feature_flags.yaml），默认关闭， 理由里写实测数字而不是期望。
  • Make the extraction produce more complete, more faithful information — for instance, making entity information reach every record about the same cell line consistently. That fixes an inconsistency; it does not loosen the ruler.
  • Fix a defect that is discarding correct results. proven The one approach that worked was of this kind: a hallucinated evidence id in the eligibility field caused an entire response — including six correct records — to be thrown away, and one of them was GO-002, another missing outcome.
  • Every change must sit behind a flag in config/feature_flags.yaml, defaulting off, with a rationale stating measured numbers rather than expectations.

必须做对照组。最近三次实验都出现过「看似有收益」的情况， 而对照组证明收益来自合并动作本身、不是那个改动。 其中一次如果没做对照，会被报成「证据准确率 +1 的成功」。 Run a control arm. The last three experiments all showed apparent gains that a control attributed to the merge itself rather than to the change under test. One of them would have shipped as "evidence accuracy +1, a success" had no control been run.

必须报告全部影响：recall、precision、evidence accuracy、 以及每一条已匹配结果有没有换配对。一个 +1 掩盖着一次错换，不算收益。 Report the whole effect: recall, precision, evidence accuracy, and whether any already-matched outcome changed assignment. A +1 that hides a swap is not a gain.

严格 Schema 的两个坑Two traps in strict schema mode

  • OpenAI 的 strict 模式要求每一个 object 都有 additionalProperties: false。 to_strict_json_schema 对自由映射会输出 true，必须强制覆盖， 用 setdefault 不起作用。
  • 把一个自由映射封死成空对象，会让「resolved 必须带 corrected_fragment」 这类约束无法被满足。正确做法是给它一个具体的字段结构，而不是封死。
  • Strict mode requires additionalProperties: false on every object. to_strict_json_schema emits true for a free-form mapping, so it must be forced — setdefault does not work.
  • Sealing a free-form mapping into an empty object makes constraints such as "resolved requires corrected_fragment" unsatisfiable. Give it a concrete field shape instead of sealing it.

9. 一条线索已查证 —— 结论是「无可修之处」 9. One lead investigated — the answer was "nothing to fix"

此前我以为：实体信息只到达了免疫荧光记录、没到达杀伤记录， 是「实体表未被一致应用」的可修缺陷。查证后，这个前提的两半都是错的。 The working theory was that the entity information reached the immunofluorescence record but not the killing record, and that this was a fixable inconsistency. Both halves of that premise were false.

实体表把群体写进了免疫荧光记录 The entity table put the population into the IF record 没有。那条记录里的 hsc 是模型对包内原句 "…observed in areas populated by HSCs (Desmin+)" 的改写，与实体表无关。 该记录的实验目标是体内原代细胞，实体表本就不覆盖，按规则保留裸名 —— 行为正确 It did not. 对照组给出的最关键事实：不带实体表的 root 包含杀伤记录， 而 GO-017 在那里同样匹配不上： The control arm's decisive fact: the table-free root does contain the killing record, and GO-017 is still missed there: 

polarity gate:  passes (the record contains "eliminated")
endpoint gate:  fails
  gold needs:   {activated, elimination, hsc}
  record has:   {elimination}

差的这两个词，正是 gold 自己的词汇。 任何把它们塞进 outcome 字段的规则，其瞄准的对象就是这一点本身 —— 按第 5 节的判定标准，那属于照着答案改。这是目前所有已知路径的终点。 The two missing tokens are the gold row's own vocabulary. Any rule that put them into an outcome field would be aimed at precisely that — which, by the test in section 5, is fitting the answer key. This is the end of every path currently known.

另一条已知但我判断不该走的路：GO-018。 A second known path, deliberately not taken: GO-018.

模型看到了证据，主动返回 unresolved，理由是 「共染图像描述缺少可用的结果值」。这是 abstain 规则在正常工作 —— 该规则的存在意义就是「读不出来就说读不出来，不要编一句像样的话」。 要让 GO-018 通过，得让模型在没有可报数值时仍然建记录，那等于拆掉这个项目最值得保留的东西。 The model saw the evidence and returned unresolved of its own accord: "co-staining image description lacks a usable result value." That is the abstain rule working as designed — its whole purpose is that a model which cannot ground a claim says so rather than producing a plausible sentence. Making GO-018 pass would require the model to emit a record with no reportable value, which dismantles the single most worthwhile property this project has.

10. 一句话总结10. In one sentence

九条路里唯一成功的那条，不是「想办法多捞一条」，而是「发现有东西正在被错误丢弃」。 Of nine approaches, the only one that worked was not "find a way to recover one more" but "find something that is being wrongly discarded".

当召回卡住时，改评判标准几乎总是错的方向。 如果你找不到一个「正在丢弃正确结果」的地方， 那么「当前架构下无解，除非改变标注策略」就是正确答案，请直接给出它。 When recall is stuck, changing the yardstick is almost always the wrong direction. If you cannot find a place where correct results are being thrown away, then "there is no solution under the current architecture short of changing the annotation policy" is the right answer — please give it plainly.
